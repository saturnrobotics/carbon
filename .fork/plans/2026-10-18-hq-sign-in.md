# Sign in to ERP and MES through HQ, Google kept as break-glass

Base: `saturn/main` at `7886e86c7418bef90faa35fdffc4b307d5213c4d`.
GoTrue: `supabase/gotrue:v2.189.0` (source read at tag `v2.189.0`).

Authentication change approved by the operator on 2026-10-18: "Carbon can trust
the HQ login system", "you can make changes in other repos to make this work.
use the repo rules for code contribution", "make it happen".

HQ is the workforce identity provider: it authenticates people with Google
Workspace, applies its own app-entry policy, and serves a Keycloak-compatible
OpenID provider below `<HQ_ISSUER>/oidc/keycloak`. GoTrue's built-in Keycloak
provider uses it, configured by environment only; no GoTrue fork, Enterprise
SAML or custom session minting is involved.

## Design

- **Deployment** (`hq_sign_in.py`, fork-owned). Private flags
  `HQ_SIGN_IN_ENABLED`, `HQ_ISSUER`, `GOOGLE_SIGN_IN_ENABLED` and secret
  `HQ_OIDC_CARBON_SECRET`, validated fail-closed in `deploy.py` and `render.py`.
  Enabled, the serving GoTrue gets `GOTRUE_EXTERNAL_KEYCLOAK_*` (client
  `carbon`, the Supabase callback as redirect URI) and the secret as a file
  mount; the bootstrap GoTrue, ERP and MES never do. `AUTH_PROVIDERS` is
  `google`, `hq,google` or `hq`. Google cannot be disabled without HQ. Disabled,
  the render is byte-identical to before.
- **Token hook** (`auth/google-domain-hook.sql`; names kept because GoTrue's hook
  URI and release inputs refer to them). Admits `provider IN ('google',
  'keycloak')` under unchanged rules: confirmed account on the domain, matching
  identity email, JSON-true `email_verified`, `custom_claims.hd` equal to the
  domain. AMR records only `oauth`, so the hook relies on these two being the
  only enabled OAuth providers.
- **Apps.** `hq` joins the `AuthProvider` union; `@carbon/auth/saturn/hq-sign-in`
  (fork-owned) holds the button, the `keycloak` OAuth call and the automatic
  start. Login loaders compute `hasHqAuth`/`autoHq` beside the existing
  `autoGoogle`. Automatic start needs HQ to be the only provider and a
  `redirectTo` (bounced from a protected page), so signing out does not sign
  straight back in; a second automatic start in one tab within a minute is
  skipped, so a refused sign-in cannot loop.
- **Accounts.** GoTrue links a new identity to the existing non-SSO account
  with the same verified email (default linking domain), so Google-created
  users gain a `keycloak` identity on first HQ sign-in. The ERP/MES callbacks
  match by email and never check the provider.

## Dependencies

- HQ serves `/oidc/keycloak/protocol/openid-connect/{auth,token,userinfo}` for
  client `carbon`: code flow without PKCE or nonce, client-secret token
  authentication, scope read as a set, unknown authorize parameters ignored,
  userinfo with `sub`, `email`, `email_verified: true`, `name`, `hd`.
- The VM accepts the tailnet subnet route to HQ (the Tailscale
  `--accept-routes` change is a separate deployment branch) and the tailnet
  policy lets `tag:carbon` reach HQ on TCP 443.

No database migration, application schema change or deployment is part of this
change.
